[OminiControl2](https://arxiv.org/abs/2503.08280) 解决的是 DiT 多 condition 控制里的 efficiency bottleneck。这篇笔记不复述论文，只回答两个我关心的问题：**成本到底从哪来**，以及**它的 evaluation 到底证明了什么、没证明什么**。

## 成本从哪来

Universal image conditioning（OminiControl 开创的做法）很灵活：把 condition 图像编码成 tokens，直接拼进 DiT 的序列里参与 attention。但代价有两层：

- Attention 对序列长度是 quadratic cost，每加一个 condition，序列就长一截；
- Condition tokens 在**每一个 denoising step 都被重新处理一遍**——而它们本身并不随时间步变化。

所以 conditional overhead 随 condition 数量和步数快速膨胀。OminiControl2 的两个对策正好对着这两层：**compact token representation**（压缩 condition tokens，缩短序列）和 **feature reuse**（condition 特征跨 denoising steps 复用，不重复算）。

## 它怎么证明 efficiency

这部分是论文最扎实的地方，evaluation spec 值得整体抄下来当模板：

- **任务**：Canny-to-image、depth-to-image、mask inpainting、image deblurring
- **数据**：Text-to-Image-2M 训练；COCO2017 validation（5,000 张）评估
- **质量指标**：FID、CLIP-Text、CLIP-Image、NIQE、MUSIQ
- **效率指标**：inference latency、condition overhead（秒 / 百分比）、parameter overhead
- **Baselines**：OminiControl、SD 1.5 + ControlNet、FLUX + ControlNet 系、token merging、naive feature caching；ablation 拆开只用 feature reuse / 只用 compact representation
- **训练**：FLUX.1 + LoRA，Prodigy optimizer，每任务 25k iterations

核心数字：multi-condition 场景下 conditional overhead 从 **24.38s 降到 0.93s**（约 96.2% reduction），同时 FID 保持 competitive。而且 speedup 是分别沿分辨率、denoising steps、condition 数量三个轴报告的——这种「效率沿多个 scaling 轴分别汇报」的写法本身就值得学。

## 它没证明什么

论文用 FID / CLIP / NIQE / MUSIQ 覆盖了「生成质量还行」，但这些都是 generic 指标——**没有专门评 control fidelity**：给了 reference/condition 之后，输出到底多忠实于它？对比之下，MICo-Bench 这类工作专门为 multi-reference composition 设计了 human-aligned 的 reference-based 指标（如 Weighted-Ref-VIEScore，带 human-verified reference 和 face-source 标注）。

两篇的 evaluation 目标其实是正交的：OminiControl2 证明 **conditioning 可以很便宜**，MICo-Bench 关心 **conditioning 是否忠实**。一个像样的 multi-condition benchmark 大概需要同时有这两组轴——efficiency 的 latency/overhead/condition-scaling 轴，加上 fidelity 的 reference/identity/prompt-alignment 轴。

---

**English takeaways**

- The cost of universal image conditioning in DiT is twofold: condition tokens lengthen the sequence (quadratic attention cost), and they get re-processed at every denoising step despite being time-invariant.
- OminiControl2 attacks exactly those two: compact token representation (shorter sequences) and cross-step feature reuse — cutting multi-condition overhead from 24.38s to 0.93s (~96% reduction) at competitive FID.
- Its evaluation proves conditioning **efficiency**, not control **fidelity**: quality is measured with generic metrics (FID/CLIP/NIQE/MUSIQ), with no reference-based faithfulness metric à la MICo-Bench's Weighted-Ref-VIEScore.
- Reporting speedup separately along resolution, step count, and condition count is a template worth stealing for any efficiency paper.
